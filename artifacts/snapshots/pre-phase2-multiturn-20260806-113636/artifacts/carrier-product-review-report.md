## 二、业务流程合理性审查

### 问题 1：搜索功能流程断裂（P2）

**现象**：页面多处搜索组件显示 "功能（0）" / "数据（0）"，搜索结果为空时不提供引导操作。

**原因**：SSR 渲染时未携带搜索索引数据，需等待 JS 执行和 API 调用后才能填充；空状态缺乏 "去首页浏览"、"查看全部应用" 等引导链接。

**影响**：用户首次进入时面对空搜索结果，产生 "平台无功能" 的错觉，增加认知负担。

**建议**：
- SSR 时预渲染热门应用/功能列表
- 空状态增加引导："浏览全部应用"、"查看最近使用"、"联系管理员开通权限"
- 搜索框增加搜索历史/快捷入口

### 问题 2：反馈流程存在信息孤岛（P2）

**现象**：反馈表单中的 "可用运维工时: 0工时"、"服务等级:" 字段显示异常值（0 和空）。

**原因**：用户未关联服务合同或服务等级未配置时，系统直接展示原始数值，未做兜底处理。

**影响**：
- 用户对 "0工时" 产生困惑——是我没有运维支持？还是系统 bug？
- "服务等级" 为空，用户无法判断自己的支持级别

**建议**：
- 增加兜底文案："联系管理员配置运维服务" 或 "您的服务等级：标准版"
- 隐藏无意义字段，改为悬停提示
- 在反馈流程中增加 SLA 预估（如 "预计 2 小时内响应"）

### 问题 3：AI 助手入口无引导流程（P2）

**现象**：ChatGPT 入口存在（GPT3.5/GPT4.0 切换），但输入框占位符仅为 "请输入内容（回车可直接发送消息）"，无场景引导。

**原因**：AI 功能缺少 Onboarding 设计，用户不知道可以问什么、能做什么。

**影响**：AI 功能使用率低下，沦为摆设。

**建议**：
- 增加快捷提问模板："如何查看充电订单？"、"帮我生成日报"、"解释这个功能的作用"
- 首次使用时展示欢迎语和功能介绍
- 根据用户角色预置不同 prompt 模板（运营/运维/管理）

## 三、功能领先性审查

### 问题 4：AI 集成停留在表层（P3）

**现象**：AI 功能仅为通用 ChatGPT 对话窗口，iframe 嵌入，无业务深度集成。

**原因**：AI 功能为快速集成方案，未与充电业务数据打通。

**影响**：
- 无法回答业务相关问题（如 "昨天某站点的充电量"）
- 无法执行操作（如 "帮我导出报表"）
- 与平台其他功能无联动

**建议**：
- **短期**：增加 RAG 知识库，接入平台帮助文档和功能说明
- **中期**：打通业务数据 API，支持数据查询和报表生成
- **长期**：构建 Agent 能力，支持 "帮我在 XX 站点创建充电策略" 等操作型指令

### 问题 5：反馈系统缺乏闭环（P3）

**现象**：反馈提交后仅展示 "我的反馈" 列表，无处理进度追踪、无满意度评价。

**原因**：反馈系统可能只完成了 "收集" 环节，未打通工单系统。

**影响**：用户不知道反馈是否被处理、何时处理，降低再次反馈意愿。

**建议**：
- 对接工单系统，反馈 = 自动创建工单
- 增加状态流转：已提交 → 已受理 → 处理中 → 待确认 → 已解决
- 增加满意度评价（NPS 评分 + 文字评价）
- 处理完成后通知用户（站内信/邮件/企微）

## 四、客户与老板视角审查

### 问题 6：运维信息暴露引起客户焦虑（P1）

**现象**：反馈页面直接展示 "可用运维工时: 0工时"。

**原因**：未区分 "内部运维人员" 和 "客户" 视角，把内部资源信息暴露给普通用户。

**影响**：
- **客户视角**："我的服务已经用完了？" "是不是没人管我了？"
- **老板视角**：资源管理信息外泄，客户可能据此压价或投诉

**建议**：
- **立即修复**：对普通用户隐藏运维工时字段
- 仅对内部人员或已签约 SLA 客户展示
- 替换为客户友好的文案："您的工单将优先处理" / "预计响应时间：2小时"

### 问题 7：缺少管理层 Dashboard 入口（P1）

**现象**：从平台框架层看，没有明显的 "数据看板"、"经营分析"、"运营报表" 入口。

**原因**：平台定位为操作层工具，缺少决策支持层设计。

**影响**：
- 老板视角：无法快速了解充电业务整体运行状况
- 管理层：需要逐个点开功能查看，效率低下

**建议**：
- 在顶部或首页增加 "运营概览" Dashboard
- 关键指标卡片：今日充电量、活跃站点数、故障率、收入趋势
- 支持一键下钻到详细报表

## 五、UI 交互主流设计审查

### 问题 8：布局高度计算异常（P2）

**现象**：多处 `style="height:NaNpx"` 出现在源码中。

```html
<div class="dashboard-main" style="height:NaNpx;display:flex;" data-v-3f2b2751>
<iframe ... style="height:NaNpx;" data-v-03944bea data-v-c045668a>
```

**原因**：高度计算依赖 JS 运行时值（如 `window.innerHeight`），SSR 阶段无 `window` 对象导致 `NaN`。

**影响**：
- SSR 阶段布局闪烁（FOUC）
- 可能导致 iframe 内容区域高度为 0
- 影响首屏体验

**建议**：
- SSR 时增加兜底高度（如 `100vh` 或 `calc(100vh - 60px)`）
- 使用 CSS 变量（`var(--layout-height, 100vh)`）
- 在 `mounted` 生命周期中重新计算并更新

### 问题 9：对话框层级管理混乱（P2）

**现象**：
- 反馈抽屉：`zIndex="30020"`
- 通知弹窗：`zIndex="40000"`
- 其他渲染对话框：`zIndex="10001"`（被注释说明 `otherRenderDialog .el-dialog__wrapper{z-index:10001!important}`）

**原因**：z-index 为硬编码分散值，缺少统一管理层级系统。

**影响**：
- 可能出现弹窗被其他弹窗覆盖的情况
- 维护困难，新增弹窗时容易冲突

**建议**：
- 建立统一的 z-index 层级规范：
  - 基础内容：0-1000
  - 固定头部/侧边栏：1000-2000
  - 模态框/对话框：2000-3000
  - 通知/Toast：3000-4000
  - 全屏遮罩/Loading：4000+
- 使用 CSS 变量管理：`--z-index-modal: 2000`

### 问题 10：移动端适配缺失（P2）

**现象**：
- `viewport` 设置为 `maximum-scale=1, user-scalable=no`
- 页面框架为桌面端布局（左侧边栏 0-380px，固定头部）

**原因**：产品设计定位为桌面端，未考虑移动场景。

**影响**：
- 运维人员可能需要现场用手机查看充电站状态
- 管理层可能在移动场景下查看数据

**建议**：
- 至少保证移动端可访问（响应式布局或独立 H5）
- 关键功能（告警查看、数据概览）支持移动端
- 取消 `user-scalable=no`，保证无障碍需求

### 问题 11："返回旧版" 按钮的位置与语义（P2）

**现象**："返回旧版" 按钮位于头部右侧工具区，样式与功能按钮一致。

**原因**：新旧版本切换是临时过渡需求，但入口过于显眼。

**影响**：
- 新用户可能误点进入旧版，产生困惑
- 长期存在会削弱新版权威感

**建议**：
- 降级为次要入口：放入用户菜单或设置中
- 增加使用引导："新版已全面升级，旧版将于 X 月下线"
- 收集返回旧版的原因数据，针对性优化新版

## 六、反人类设计与易用性审查

### 问题 12：帮助中心建设中（P1）

**现象**：帮助中心显示 "帮助系统建设中"，且为空白页面。

**原因**：帮助文档未准备好就上线了入口。

**影响**：
- 用户遇到问题时无处可查
- 客服压力增大
- 平台专业度受损

**建议**：
- **立即**：至少提供基础 FAQ 和常用功能操作指南
- 接入 AI 知识库（已有 ChatGPT，可先用 RAG 方案）
- 每个功能页面增加 "?" 帮助图标，链接到对应文档

### 问题 13：新功能提醒的阻断设计（P1）

**现象**："新功能提醒" 使用全屏遮罩/弹窗形式，需用户主动点击 "我知道了" 或 "立即体验" 才能关闭。

**原因**：采用强提示方式确保用户看到新功能。

**影响**：
- 每次登录都弹窗，打断工作流
- "立即体验" 按钮导向的 "自动启动功能列表" 概念不清晰
- 没有 "不再提醒" 选项

**建议**：
- 改为非阻断式提示（如顶部横幅、Badge 红点）
- 增加 "今日不再提醒" / "已了解" 选项
- 功能说明需更直观：用 GIF 或截图展示 "自动启动" 的效果

### 问题 14：反馈描述字数限制过严（P1）

**现象**：问题描述 textarea 限制 `maxlength="255"`。

**原因**：限制字段长度以控制数据库存储。

**影响**：
- 复杂问题无法描述清楚（如包含报错堆栈、复现步骤、截图说明）
- 用户被迫删减关键信息

**建议**：
- 放宽至 2000 字或不限字数
- 增加富文本编辑（支持加粗、列表、代码块）
- 已支持附件上传，建议在描述区提示 "详细描述 + 截图附件"

## 八、总体评价

### 优势
1. **平台架构规范**：基于 Nuxt.js SSR + Element UI，组件化程度较高
2. **国际化支持**：内置 zh-CN/en-US/pt-BR/zh-HK 多语言框架
3. **AI 前瞻布局**：已接入 ChatGPT（GPT3.5/4.0），具备扩展潜力
4. **反馈系统完整**：分类明确、支持附件、有反馈中心

### 劣势
1. **内容层缺失**：帮助中心建设中、搜索无引导、空状态体验差
2. **视角单一**：侧重操作层，缺少管理层/老板视角的决策支持
3. **信息暴露风险**：运维资源信息直接展示给客户
4. **AI 浅层集成**：仅 iframe 嵌入，未与业务打通

### 建议路线
- **短期（1-2 周）**：修复信息暴露、补齐帮助中心、优化反馈体验
- **中期（1-2 月）**：AI 业务知识库、管理层 Dashboard、反馈闭环
- **长期（3-6 月）**：移动端适配、AI Agent 能力、数据驱动运营
